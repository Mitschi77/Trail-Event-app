# NORTHBOUND – Strava Phase 1 setup

This phase implements a personal Strava connection for the app owner. It does not enable multi-athlete access and does not deploy anything to the production Supabase project by itself.

## Strava application

The existing Strava application is retained. Its Authorization Callback Domain must be:

\`oycfmdovrnvhcwxmpanl.supabase.co\`

The exact OAuth redirect URI generated by the Edge Function is:

\`https://oycfmdovrnvhcwxmpanl.supabase.co/functions/v1/strava-callback\`

Strava's setting accepts the callback domain only (no scheme and no path).

The app requests only \`read,activity:read_all\`. It does not request write access.

## Supabase Function Secrets

Keep the existing \`STRAVA_CLIENT_ID\` and \`STRAVA_CLIENT_SECRET\` secrets. Do not rotate or expose them.

Add \`STRAVA_TOKEN_ENCRYPTION_KEY\` as a new Edge Function secret. Generate a random 32-byte key and store its Base64 representation, for example with:

\`\`\`sh
openssl rand -base64 32
\`\`\`

Never commit this key or share it in chat. The Edge Functions use AES-256-GCM to encrypt both access and refresh tokens before storing them.

The app return URL defaults to \`https://mitschi77.github.io/Trail-Event-app/\`. If the app URL changes, set \`NORTHBOUND_APP_URL\` as a Function Secret to the new trusted URL.

## Functions

- \`strava-connect\`: authenticated start/status/disconnect actions; JWT verification stays enabled.
- \`strava-callback\`: public GET callback; the one-time, 10-minute OAuth state is validated server-side; JWT verification is disabled only for this callback.
- \`strava-sync\`: authenticated manual activity sync; JWT verification stays enabled.

The callback domain and redirect URI must match the registered Strava app. Do not deploy the callback before confirming the domain setting.

## Data and privacy

- OAuth state hashes and encrypted tokens are stored in server-only tables.
- RLS is enabled on all three tables.
- Only the authenticated owner can read their normalized Strava activities.
- Client-side writes to imported activities are denied.
- GPS streams, route polylines, heart-rate data, and calories are not imported in this phase.
- Disconnect revokes the Strava refresh token and removes the stored connection. Imported activity summaries are retained; deleting them is a separate user decision.
- Initial backfill is paginated in batches of up to 200 activities. Pressing Sync again continues older history until complete. Incremental sync overlaps the last three days to catch provider edits.

## Deployment order

1. Review and merge the code PR only after CI and security review.
2. Apply \`supabase/migrations/20261125090000_strava_phase1.sql\`.
3. Add \`STRAVA_TOKEN_ENCRYPTION_KEY\` in Supabase Function Secrets.
4. Deploy \`strava-connect\` (verify JWT on), \`strava-callback\` (verify JWT off), and \`strava-sync\` (verify JWT on).
5. Change the Strava Authorization Callback Domain to \`oycfmdovrnvhcwxmpanl.supabase.co\`.
6. Add the app UI that calls these functions and test the complete owner-only OAuth flow.

## Important limitation

The Phase 1 backend does not yet add buttons to the GitHub Pages interface. UI wiring and mapping imported activities into the app's existing personal running-history model are the next implementation step. Existing FIT/TCX/GPX imports remain unchanged.
